# 0005 エラー応答は RFC 9457 Problem Details 形式にする

## 背景

エンドポイントごとにエラー応答の形が違い（`{"error": "..."}`、`{"detail": "..."}`、文字列のみの3種類）、フロントエンドでエラー表示の分岐が増えている。入力検証エラーでは、どの項目が誤っているかを画面に出したい。

## 決定

4xx・5xx の応答はすべて `application/problem+json`（RFC 9457）にし、入力検証エラーは拡張メンバー `errors` に項目ごとの理由を入れる。

## 検討した選択肢

### RFC 9457 Problem Details

- 利点: 標準の形式で、外部の API 利用者にも説明が要らない。`type` で種類を機械的に見分けられる
- 欠点: FastAPI の既定のエラー応答と形が違うため、例外ハンドラーを書き換える必要がある

### FastAPI 既定の `{"detail": ...}` に統一する

- 利点: 追加の実装がほぼ要らない
- 欠点: `detail` の型が文字列とリストで揺れ、フロントエンドの分岐が残る

## 結果

- フロントエンドのエラー表示は `type` と `errors` だけを見ればよくなる
- エラーを返すコードは共通の例外クラスを使い、レスポンスを直接組み立てない
