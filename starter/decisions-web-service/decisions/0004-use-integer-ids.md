# 0004 リソースの ID は連番の整数にする

## 背景

タスク・ボード・コメントの各リソースに、URL とデータベースで使う ID が必要。データベースは [0002](0002-store-data-in-sqlite.md) の SQLite で、ID の生成はデータベースに任せたい。

## 決定

ID は SQLite の `INTEGER PRIMARY KEY` による連番の整数にし、URL にもそのまま使う（例: `/tasks/42`）。

## 検討した選択肢

### 連番の整数

- 利点: データベースが自動で振る。URL が短く、口頭でも伝えられる
- 欠点: 件数が外から推測できる。複数のデータベースをまたぐと重複する

### UUID v4

- 利点: どこで生成しても重複しない。件数が推測できない
- 欠点: URL が長い。生成順に並ばないため、索引の効率が落ちる

## 結果

- URL を `/tasks/42` の形で共有できる
- データベースを分割・統合するときは ID の振り直しが必要になる
