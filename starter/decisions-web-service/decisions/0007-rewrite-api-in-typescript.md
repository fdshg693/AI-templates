# 0007 API サーバーを TypeScript で書き直す

## 背景

フロントエンド担当から、API のリクエスト・レスポンスの型を手で TypeScript に書き写しており、項目の追加漏れが8月に2件起きたと報告があった。API サーバーを TypeScript で書き直せば型定義を共有できる、という提案が出た。API のエンドポイントは現在34本。[0001](0001-use-python-fastapi.md) の見直し条件（p95 300ms 超）には当たっていない。

## 決定

API サーバーは TypeScript で書き直さない。型の書き写しは、OpenAPI 仕様からの TypeScript 型の自動生成に置き換える（ツール選定は実装作業の中で行い、判断としては残さない）。

## 検討した選択肢

### TypeScript で書き直す

- 利点: フロントエンドと型定義を直接共有できる
- 欠点: 34本の書き直しに約6週間かかり、その間は機能追加が止まる。3人中1人は TypeScript を書けない

### OpenAPI 仕様から型を自動生成する

- 利点: 書き直しが要らない。[0001](0001-use-python-fastapi.md) で OpenAPI 仕様を自動生成にしているため、追加作業は生成手順の整備だけで済む
- 欠点: 型の生成をフロントエンドのビルド手順に組み込む必要がある

## 結果

- [0001](0001-use-python-fastapi.md) は変更しない
- 型の書き写しによる追加漏れは、生成手順の整備後に起きなくなる
