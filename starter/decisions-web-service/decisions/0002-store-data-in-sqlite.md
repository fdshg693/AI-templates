# 0002 データは SQLite に保存する

## 背景

最初のリリースは社内の1チーム（約20人）だけが使う。サーバーは1台の VM で、運用担当はいない。データベースのバックアップと障害対応に割ける時間は月2時間程度。

## 決定

データは VM 上の SQLite ファイル1つに保存し、夜間にファイルごとオブジェクトストレージへコピーしてバックアップとする。

## 検討した選択肢

### SQLite

- 利点: 別サーバーが要らず、バックアップはファイルのコピーで済む。運用作業がほぼ無い
- 欠点: 書き込みが同時に1つしか走らない。サーバーを2台以上にできない

### マネージド PostgreSQL

- 利点: 同時書き込みとサーバーの複数台化に対応できる。バックアップはサービス側が行う
- 欠点: 月額費用がかかる。20人規模では性能面の利点が出ない

## 結果

- 運用作業をほぼ無しで始められる
- サーバーを複数台にするには、データベースの移行が先に必要になる
- 利用チームが3つ以上になる、または書き込み待ちによるタイムアウトが週1回以上出たら見直す
