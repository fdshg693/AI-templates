# 判断を置き換える

`accepted` の判断がもう成り立たなくなったとき（前提が変わった、運用して問題が出た）に読む。書式は [decision-writing.md](decision-writing.md) が正本。

## 守ること

- `accepted` になった判断の本文（`## 背景` 以降）は書き換えない。理由: 当時なぜそう判断したかが失われ、同じ失敗を繰り返す原因になる。誤字・リンク切れの修正だけは許す。
- 変えるのは新しい判断ファイルを足すことで行う。古い判断で変えてよいのは frontmatter の `status`・`date`・`superseded_by` だけ。
- `supersedes` と `superseded_by` は必ず対で書く。理由: 片方だけだと、古い判断を読んだ人が後継に辿り着けない（lint が検査する）。

## 手順

1. 置き換える判断を読み、新しい判断の `## 背景` に「`NNNN` の前提のうち何が変わったか」を書けるようにする。
2. [decision-writing.md](decision-writing.md) の手順で新しい判断を `status: proposed` で作り、`supersedes: [NNNN]` に古い番号を書く。複数の判断をまとめて置き換えるならすべて並べる。
3. 古い判断は `proposed` の間は変更しない（不採用になる可能性があるため）。
4. 新しい判断が `accepted` になったら、同じ変更で古い判断を次のように更新する。
   - `status: superseded`
   - `superseded_by: [新しい番号]`（既に値があれば追加する）
   - `date` を当日に更新
5. 新しい判断が `rejected` になったら、古い判断は変更しない。新しい判断の `supersedes` は残してよい（何を覆そうとしたかの記録になる）。
6. lint を実行し、エラー0にする。

一部だけを変える場合も、変わらない部分を新しい判断の `## 決定` に書き直して全体を置き換える。理由: 「一部置き換え」を許すと、有効なルールを知るために複数ファイルを突き合わせる必要が出る。

## 完了条件

- [ ] 新しい判断の `supersedes` と、古い判断の `superseded_by` が互いを指している（新しい判断が `accepted` の場合）
- [ ] 古い判断の本文に差分が無い（frontmatter 以外）
- [ ] lint がエラー0で終わる
