# スキーマと検証

## スキーマの正本はコード1か所

キー・型・必須・許容値・配置パス・ステータスの意味は [`schema.py`](../references/tools/vault/schema.py) にだけ書く。

- 人間向けの一覧 `docs/vault-schema.md` は `gen_schema_doc.py` が生成する。ルール文書（`AGENTS.md` 等）にフィールド表を書き写さない。
- 読む側のコード（ダッシュボード・索引・重複チェック・圧縮）は、ステータスのラベル・並び順・分類を `schema.py` から引く。値のリストをコードに書き写すと、ステータスを1つ足したときに直し漏れる。

サンプルの `schema.py` は標準ライブラリの dataclass で書いた宣言的な定義（依存は PyYAML だけ）。規模が大きくなったら Pydantic などのバリデーションライブラリに移してよい。その場合も「正本は1か所、文書は生成物」は変えない。

## エラーと警告の2段階

| レベル | 例 | 扱い |
| --- | --- | --- |
| エラー | 型・許容値の違反、未知のキー、必須キーの欠落、フォルダ名とキーの不一致、台帳と生きたフォルダの二重登録 | `validate.py` は常に失敗。commit させない |
| 警告 | スコアに幅が無い、終了したのに理由が無い、期限切れの `next_due`、参照先キーが無い、派生文書の同期漏れ | `--strict` のときだけ失敗 |

警告をエラーにしないのは、記入途中のファイルでも読み込み・検索を止めないため。ローダーは1ファイルの記入ミスで全体を止めず、問題を `issues` に集めて読めた範囲を返す。

## 検査の3種類

1. **値の検査**（1ファイルで完結）: 型・許容値・範囲・形式。`schema.py` の `F` の定義から機械的に行う。
2. **運用ルールの検査**（1ファイルで完結）: 「min と max は両方書く」「終了したら理由を書く」など。`schema.py` の `LINTS` に種別ごとの関数で書く。
3. **関係の検査**（複数ファイル・今日の日付に依存）: キー参照の存在、二重登録、期限切れ、派生元との同期。`vaultlib.py` の `_check_relations` で行う。

## 配置とキーを一致させる

- エンティティの `key` はフォルダ名、コンタクトの `contact_key` はフォルダ名と一致させる。
- イベントログの `date` / `kind` はファイル名（`{YYYY-MM-DD}_{kind}.md`）と一致させる。
- `scope` は配置先の scope フォルダと一致させる。

パスと frontmatter の両方に同じ情報があるのは冗長に見えるが、ファイルを別の場所にコピーしたり、frontmatter だけを抜き出して扱ったりしたときにも自己完結するため。不一致は検証が必ず拾う。

## 参照はキーで書く

frontmatter には他ファイルのパスを書かず、キー（`contact: "vendor_sato-hanako"`）を書く。パスの組み立てはローダーが行う。フォルダ構成を変えても frontmatter を書き換えずに済み、参照切れはキーの存在確認で検出できる。本文中のリンクは相対パスで書く（絶対パス・`file:///` は使わない）。

## 値の書き方

- 金額・数量は単位を決めて整数で持つ（サンプルの費用は「円/月」）。単位の補足は `*_note`。
- 期限は `YYYY-MM-DD` か `YYYY-MM-DD HH:MM`。
- 空文字は「未記入」と同じ扱い。
- 未知のキーはエラーにする。タイプミス（`staus:`）を黙って通さないため。

## commit 前に必ず通す

検証は人間・AI の記憶に頼らず、commit フックで強制する。lefthook を使う場合の例:

```yaml
pre-commit:
  commands:
    vault-validate:
      glob: ["vault/**/*.md", "tools/vault/**/*.py"]
      run: uv run tools/vault/validate.py
    vault-schema-doc:
      glob: ["tools/vault/schema.py", "docs/vault-schema.md"]
      run: uv run tools/vault/gen_schema_doc.py --check
```

## スキーマを変えるとき

同じ変更の中で「`schema.py` の修正 → 既存ファイルの移行 → 文書の再生成 → 読む側の対応 → 検証エラー 0」まで行う。途中で止めると、スキーマと実データが食い違った状態が残る。手順はコピー先のルート [AGENTS.md](../references/AGENTS.md) に書いてある。
