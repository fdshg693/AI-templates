# ルール

採用ツール方針

- スクリプト言語・ビルドツールは （デフォルトのツール） を使う。複数選択肢がある場合は、シンプルな方を選ぶ。
  - 仮想環境・依存関係の管理方法（例: ルート直下で共有するか、プロジェクトごとに作るか）をここに明記する
- 各プロジェクトには実行を簡略化する `justfile` を置く
  - justfile は行をまたいで変数を保持できない等、無理なワンライナーを作りがちな側面がある
  - プロジェクトが複雑になる場合は、`justfile` ではなく `Taskfile`（`Taskfile.yml` 等）を使う
  - **無理なワンライナーを埋め込まず、ファイル分割・スクリプト分離等で可読性を保つこと**

コード品質

- 難しい部分にはコメントを付けて理解を助ける
- 環境変数からの値取得に加えて、シンプルな `.env` からの値取得もサポートする（`.gitignore` 済み）
  - 対応する `.env.example` も用意する

ガードレール

- 明示的な指示がない限り、実際の環境への反映（デプロイ・課金の発生する操作等）は行わない
  （コードの作成とローカルでの動作確認までを行う）
  - ユーザーからの明示的な指示があった場合のみ実行してよい
  - 読み取り系の操作は比較的害が少ないので、原因調査や確認のためには実行してよい
- 学習目的のプロジェクトでは、一度動かして終わりにせず、設定を変えると結果がどう変わるかを
  実際に操作して体験するところまで行う

## 各プロジェクト共通ファイル構成

細かく分ければよいわけではなく、可読性・理解しやすさを最優先に分割する。

- `justfile`：セットアップ・設定生成・ローカル実行などのコマンドをまとめる
  - プロジェクトが複雑になる場合は `justfile` ではなく `Taskfile` を使う
- `README.md`：このプロジェクトで行う内容・手順・学習の流れ
- `KNOWLEDGE.md`：このプロジェクトで新たに出た用語・概念（前のプロジェクトでカバー済みの語は含めない）
- `PLAN.md`（任意）：そのプロジェクト固有の設計（大きめのプロジェクトのみ、かつ明示的に必要な場合に作成）
- `MERMAID.md`（任意）：構成・フローを mermaid で表現
- `{tool}.*`（任意）：内容に応じて、環境構築用の設定ファイル（IaC 等）を配置。適切なファイル分割を行い、可読性を保つ
- `questions/`（任意）：学習中に出た質問をまとめる。単なる Q&A でなく、学習すべき内容の整理となるように体系化する

## ドキュメント管理

プロジェクトを追加・更新したら、作業の最後に次のファイルを更新する。

- `study/AGENTS.md`：各テーマの概要を短く書く。AI はここを読んでユーザーの理解度を把握し、回答・提案のレベル感を調整する
- `study/{topic}/AGENTS.md`：テーマごとの学習内容（プロジェクト早見表・学習済みの概念・まだ触れていない主要概念）。
  次のプロジェクト作成の目安にする
  - このファイルが長くなったら、各プロジェクトの詳細な経緯を `study/{topic}/HISTORY.md` に、
    今後のロードマップを `study/{topic}/PLAN.md` に分け、`AGENTS.md` には現状まとめだけを残す

`sandbox/{topic}/` も同じルールに従う。

## 進め方

- **サブフォルダは独立しているので、必要ない限り今回対象となるプロジェクト範囲内に検索を絞り、
  プロジェクト直下の README 等を読んで、今回関連するプロジェクト概要のみを理解すること**
  - 逆に、無関連なプロジェクトの内容などをあれこれ確認しないこと。確認するにしても、
    README などを読んで概要を理解する程度にとどめること
