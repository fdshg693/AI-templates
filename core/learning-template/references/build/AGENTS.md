## `build/{project}` 配下の方針（学習用フォルダとの違い）

このフォルダは「学習のための反復可能な構成」より「実際に動かし続けられること」を優先する。
`study/{topic}/{project}` の標準ファイル構成（README/KNOWLEDGE/PLAN/MERMAID/questions）を
**ベースラインとしつつ、次の点で自由度を認める**。

- **IaC・構築ツールはプロジェクトごとに最適なものを選んでよい**（`study/` 側で決めたデフォルトに
  縛られる必要はない）。選定理由が非自明な場合は `README.md` に一言残す
- **標準セット以外のドキュメントを追加してよい**（例: `COST.md`（運用コストの記録）、
  `TROUBLESHOOTING.md`（詰まった箇所と対処）、`DECISIONS.md`（設計判断の記録）など）。
  ただし増やしすぎて README から辿れなくなるのは避け、追加したファイルは必ず `README.md` から
  リンクする
- **`KNOWLEDGE.md` は必須ではない**（新出用語の整理より、実際の仕様・運用のほうが優先度が高いため）

一方で、次の最低限は `study/` 側と共通のまま維持する。

- `README.md`：このプロジェクトが何で、何をどう動かすかの入口
- 実行コマンドをまとめる `justfile` または `Taskfile.yml`

あわせて、`build/` 固有のファイルとして次を推奨する。

- `BACKLOG.md`（推奨）：今後の拡張・未対応事項の一覧。`study/` 側の `PLAN.md`（学習ロードマップ・プロジェクト固有の設計）とは役割が違うため、名前を分けている
