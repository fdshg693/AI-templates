# 核となる4つの原則

このテンプレートが前提にしている考え方。ドメイン（Azure・言語学習・楽器・料理…何でもよい）に関わらず共通する。

## 1. 学習の「目的」でトップフォルダを完全に分ける

同じ技術領域でも、次のように目的が違えば置き場所を分ける。

- 手を動かして試す（実装して壊して直す）
- 座学として読む（実装せず概念だけ整理する）
- 外部リソース（クラウド・課金環境等）を使わずローカルだけで完結させる
- 学習の枠を超えて、実際に使うものを本気で作る
- 学習記録ではない、単なる操作リファレンス・チートシート

これらを1つのフォルダに混ぜると、「これは学習記録なのか、実用ドキュメントなのか」が曖昧になり、
AIも人間も読むたびに文脈を推測するコストを払うことになる。最初から目的別にフォルダを割ると、
フォルダ名を見るだけでそこに何を書くべきかが決まる。

詳しい分け方は [02-layout.md](./02-layout.md)。

## 2. トピック→プロジェクト（ステップ）の二段階で細分化し、易→難で積み上げる

各トップフォルダの中は、まず「トピック」（技術領域・ドメイン内の1テーマ）で分け、
その中を「プロジェクト」（1テーマ内の1ステップ）でさらに分ける。

- 1プロジェクト = 主役となる概念を1〜2個に絞る（欲張らない）
- 新しいプロジェクトは、直前までのプロジェクトを土台に「前回と何が変わったか」が
  説明できる粒度で積む
- 難易度は入門→中級→発展の順に並べ、後から見て学習順がわかるようにする

これにより、「今どこまで理解していて、次に何を学ぶべきか」が常にフォルダ構造から追える。

## 3. 各階層に「そこで何を書くべきか」を強制するAI向け指示ファイルを置く

人間がドキュメント構成のルールを覚えて毎回守るのは続かない。そこで各階層に
AI向けの指示ファイル（`AGENTS.md`）を置き、AIがファイルを作成・更新するたびに
構成のルールを強制する。これにより：

- 新しいトピック・プロジェクトを作るたびに、同じファイル構成が再現される
- ドキュメントの粒度（現状まとめ／詳細経緯／今後の計画）がぶれない
- 人間は「このリポジトリで何をどこに書くか」を都度考えなくてよい

詳しくは [03-agent-instructions.md](./03-agent-instructions.md)。

## 4. 指示ファイルは正本を1つに絞り、他は正本を参照するだけにする

Claude Code は `CLAUDE.md`、他のAIツールは `AGENTS.md` など、ツールごとに読みに行く
規約ファイル名が異なる。これを別々に育てると内容が食い違っていく。

そこで **`AGENTS.md` を正本とし、`CLAUDE.md` はその1行 import（`@./AGENTS.md`）のみにする**。
更新はAGENTS.md側にのみ行い、CLAUDE.md側は触らない。同じ理由で、ドキュメントが増えて
「今の理解のまとめ」と「経緯の記録」が同じファイルに混在して読みにくくなったら、
役割ごとにファイルを分割する（詳細は [03-agent-instructions.md](./03-agent-instructions.md)）。
