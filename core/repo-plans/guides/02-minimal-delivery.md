# フェーズ2ガイド: 最小実装と初回利用

`02-minimal-delivery/` に計画を作成・更新するときだけ読む。ファイル名と `status` は [plan-format.md](plan-format.md)、節の構成は [plan-skeleton.md](plan-skeleton.md) に従う。

## 進め方

1. フェーズ1の決定を確認し、利用者から観測できる最小の縦切りだけを実装対象にする。
2. 実装と同時に、最小の利用方法と再現可能な検証を用意する。
3. 既存のルール・スキルを読んで使い、作業中に実証された不足だけを追加する。
4. 動作する成果をユーザーへ示し、利用感または期待との差分をレビューしてもらう。
5. フィードバックを反映し、今回繰り返された知見だけを恒久文書へ移す。

## 計画に書くこと

骨格の「計画」節に次を書く。

- 実装範囲: 完成時の動き（実行例）と、エラーにする入力。
- 変更対象: 作るファイルの一覧。「これ以外は作らない」と明記する。
- 利用・検証の入口: 利用者が再現できる実行手順と、自動テストまたは再現手順。
- 今回作らないもの: 依存関係、設定、抽象化、将来用の機能。
- 実装中に追加した計画外の事項: 理由と、利用者向け機能かどうか（完了時に記録する）。

仕様に書かれていない挙動に気づいたら、[未規定事項の扱い](interaction-loop.md#未規定事項の扱い)に従う。

## この段階でしないこと

- 将来の機能を先回りして実装しない。使われない抽象化は、次の縦切りで前提が変わったときの変更範囲を広げるため。
- 単発の実装経緯をルールまたはスキルに移さない。
- デモや検証結果を見せずに、最小実装を完了扱いにしない。
