# フェーズ3ガイド: 基盤の定着

`03-foundation/` に計画を作成・更新するときだけ読む。ファイル名と `status` は [plan-format.md](plan-format.md)、節の構成は [plan-skeleton.md](plan-skeleton.md) に従う。

## 進め方

1. 最小実装で実証された構造、変更時の注意、利用・検証手順を集める。
2. 恒久的な情報の正本を、下の置き場所のいずれか一つへ配置する。
3. 常時守る制約はルール、必要時に読む反復手順はスキル、長い理由は設計文書に分ける。判断基準は [AGENTS.md の「ルール化とスキル化の基準」](../AGENTS.md#ルール化とスキル化の基準)。
4. 文書の入口とルールの内容をユーザーにレビューしてもらい、期待と異なる情報の置き場を修正する。
5. 次の縦切りを始めるときに読む場所と、今後改善すべき未決事項を残す。
6. ルートの指示ファイルに足した「`repo-plans/AGENTS.md` に従う」旨の1行を外す。以後の機能追加は repo-plans ではなく通常の計画運用で扱うため。

## 計画に書くこと

骨格の「計画」節に次を書く。

- 実装から観測できた知見: 実例（デモで起きたこと、検証で見つかったこと）を添える。
- 正本の置き場の表: 「情報」「正本の置き場」「理由」の3列。作らないと決めたものも「作らない」として載せる。
- 規約・案内文に入れる文面の案: そのままレビューできる形で書く。

## 置き場所の原則

| 情報                                 | 置き場所                                 | 役割                             |
| ------------------------------------ | ---------------------------------------- | -------------------------------- |
| 今回の目的、選択肢、未決事項、進捗   | `repo-plans/`                            | 一時的な計画と判断の記録         |
| リポジトリの構造と利用者向け導入方法 | ルートの README または `docs/`           | 人とエージェントが最初に読む案内 |
| 常に守る制約と確認手順               | エージェントが自動読込するルールファイル | 作業中の判断を安定させる短い規約 |
| 特定の反復作業の手順と判断基準       | スキルの配置場所                         | 必要なときだけ読む再利用手順     |
| 実行可能な設定、依存関係、生成定義   | 対象ツールが読む設定ファイル             | 宣言・自動化の正本               |
| 調査ログ、設計の詳細な根拠           | `docs/` または `repo-plans/progress/`    | 将来の判断に必要な背景           |

同じ事実を複数箇所へ転記しない。参照元を一つ決め、他の文書からリンクする。

## この段階でしないこと

- 実例のないディレクトリ、ルール、スキルを増やさない。推測で書いた手順は、実際の作業で初めて分かる不具合を含むため。
- 同じ情報を複数の正本に複製しない。
- エージェントの自己レビューだけで基盤が十分だと判断しない。
