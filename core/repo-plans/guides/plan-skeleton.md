# 計画の骨格

全フェーズ共通の計画ファイルの骨格。新しい計画は、下のコードブロックを [plan-format.md](plan-format.md) の命名で作ったファイルへコピーし、`（…）` を書き換える。フェーズごとに「計画」節へ書く中身は、各フェーズのガイドの「計画に書くこと」に従う。

記入例は [references/](../references/README.md) にある。新しい計画はこの骨格の `##`・`###` 見出しをすべて残し、まだ書けない節には「未記入（理由）」と書く。見出しの括弧書きは省略してよい。「計画」節の中の `###` はフェーズのガイドに合わせて自由に立てる。

[lint_repo_plans.py](../lint_repo_plans.py) は、次の見出しがあることを検査する（`## フェーズ完了ゲート` は `complete` のときだけ必須）。見出しを変えるときは、lint の `PLAN_SECTIONS` も同時に更新する。

- `## 目的と対象外`・`## 前提`・`## 計画`・`## 完了条件と検証方法`・`## ユーザーとの対話`・`## 未決事項と引継ぎ`
- `## ユーザーとの対話` の下の `### 質問`・`### レビュー項目`・`### 回答と反映`

```markdown
---
type: Repository Phase Plan
status: drafting
---

# （フェーズ名）: （この計画で扱う縦切り）

## 目的と対象外

- 目的: （利用者または呼び出し元から観測できる成果を1〜2行で）
- 対象外: （今回扱わないものを列挙する）

## 前提

- （前フェーズからの引継ぎ、読んだ既存ファイル、ユーザーが確認済みの事実）

## 計画

（フェーズガイドの「計画に書くこと」の項目）

## 完了条件と検証方法

- [ ] （観測可能な完了条件。確かめるコマンドや手順を併記する）

## ユーザーとの対話

### 質問（回答まで、その判断に依存する作業を進めない）

1. （選択肢・影響・推奨案を添えた質問）

### レビュー項目（作業後に確認してもらう）

- （観測可能な成果と、確認してほしい点）

### 回答と反映

| 受け取った内容 | 採否と理由 | 変更した箇所 |
| -------------- | ---------- | ------------ |
|                |            |              |

## 未決事項と引継ぎ

- （次の計画・次フェーズへ渡す事項。ルールやスキルへ移した知見は移した先を書く）

## フェーズ完了ゲート

（complete にする直前に、phase-gate.md の共通チェックリストとフェーズ別項目を貼り付けて確認する）
```
