# 対話ループのガイド

計画の初期案を作った後、ユーザーの決定またはレビューを必要とする場面で読む。すべてのフェーズで適用する。

## 使い分け

| 状況                                   | 行うこと                     | 進め方                                                                   |
| -------------------------------------- | ---------------------------- | ------------------------------------------------------------------------ |
| 回答がないと方針を選べない             | 質問する                     | 選択肢、影響、推奨案を短く示し、回答までその判断に依存する作業を進めない |
| 方針は決まったが成果の適合を確認したい | レビューまたはデモを依頼する | 観測可能な成果と、確認してほしい点を示す                                 |
| フィードバックを受けた                 | 計画を改訂する               | 回答、採否、変更した完了条件・対象外・手順を記録する                     |
| フィードバックが新たな未決事項を生んだ | 初期案へ戻す                 | 次の質問を明記し、完了扱いにしない                                       |

## 最小記録

- 誰に何を確認したか。
- 回答またはレビュー結果。
- 採用・見送りの判断と理由。
- 計画のどの項目を変更したか。

自己レビューは有用だが、ユーザーとの対話の代わりにはならない。外部の意思決定が必要な事項を、エージェントが推測で確定しない。

## 未規定事項の扱い

フェーズ2以降で、仕様に書かれていない挙動や前提に気づいたときの基準。

| 条件                                                                                 | 扱い                                                         |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 利用者から見える挙動・対象範囲・出力形式・依存関係に影響する、または後から変えにくい | フェーズ1の計画へ戻して質問にする。回答までその部分を実装しない |
| 内部実装に閉じ、利用者に見えず、後から安く変えられる                                 | フェーズ内で決めてよい。決めた内容と理由を計画に記録する     |
| どちらか判断がつかない                                                               | 戻す側に倒して質問する                                       |

フェーズ内で決めた事項も、完了前にレビュー項目として提示し、ユーザーの確認を記録する。確認前の値を確定事項として扱わない。
