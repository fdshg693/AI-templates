# 計画ファイルの書式

計画ファイルの配置・命名・frontmatter・`status` の正本。ほかの文書はここへリンクし、値を再定義しない。[lint_repo_plans.py](../lint_repo_plans.py) はこの定義に従って検査する。

## 配置と命名

パスはすべて `repo-plans/` からの相対パス。`{x}` は置き換えるプレースホルダ。

| 種類       | パス                                    | 例                                                   |
| ---------- | --------------------------------------- | ---------------------------------------------------- |
| フェーズ計画 | `{NN}-{phase}/{MM}-{slice}.md`          | `01-specification-and-technology/01-first-slice.md` |
| ラフ案     | `rough/{MM}-{topic}.md`                 | `rough/01-initial-idea.md`                           |
| 詳細記録   | `progress/{NN}-{topic}.md`              | `progress/01-technology-research.md`                 |
| 状態ファイル | `asis.md`、`phase-status.md`（直下）   | テンプレートに同梱。書き換えて使う                   |

- `{NN}-{phase}` は `01-specification-and-technology`、`02-minimal-delivery`、`03-foundation` の3つに固定する。フォルダはそのフェーズを始めるときに作る。
- `{MM}` はフェーズ内の通し番号（`01` から）、`{slice}`・`{topic}` は英小文字とハイフンの短い名前。
- **1計画 = 1ファイル**。初期案・対話と改訂・完了は、同じファイルを更新しながら `status` で表す。状態ごとに別ファイルを作らない。
- フェーズが大きくなったら、完了条件ごとに計画ファイルを分ける（`01-…md`、`02-…md`）。

## frontmatter

```yaml
---
type: Repository Phase Plan   # ラフ案は Repository Rough Plan
status: drafting
---
```

## フェーズ計画の status

| status     | 意味                                                         | 次へ進む条件                                                   |
| ---------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| `drafting` | 初期案を作成中、または初期案を提示して回答を待っている       | 回答・フィードバックを受け取ったら `revising`                  |
| `revising` | 回答を反映して改訂中、または改訂案を再提示して確認を待っている | [フェーズ完了ゲート](phase-gate.md)を満たしたら `complete`     |
| `complete` | 完了ゲートを満たし、後続へ渡す事項を記録した                 | なし。以後の変更は新しい計画にする                             |

- 回答が新しい未決事項を生んだら `revising` から `drafting` へ戻してよい（[対話ループ](interaction-loop.md)）。
- `complete` にする計画には、末尾に `## フェーズ完了ゲート` 節を置き、チェックリストをすべて `- [x]` にする。`- [ ]` が1つでも残る計画を `complete` にしない。

## ラフ案の status

| status     | 意味                                                       |
| ---------- | ---------------------------------------------------------- |
| `drafting` | 仮説・着想を書いている。未確認の事項は「未確認」と明記する |
| `promoted` | フェーズ1の計画を作り始めた。末尾の「詳細計画への移行先」に計画へのリンクを書く |
| `dropped`  | 採らないと決めた。理由を1行残す                            |

ラフ案には `## 依頼の原文`・`## 何をしたいか`・`## まだ決めていないこと`・`## 次にすること`・`## 詳細計画への移行先` の節を置く（`lint_repo_plans.py` が検査する）。`promoted` のときは「詳細計画への移行先」に計画へのリンクを書く。記入例は [references/rough/01-worklog-idea.md](../references/rough/01-worklog-idea.md)。

## phase-status.md の状態との対応

[phase-status.md](../phase-status.md) はフェーズ単位、`status` は計画単位の状態である。

| phase-status.md | そのフェーズの計画ファイル                                       |
| --------------- | ---------------------------------------------------------------- |
| `未開始`        | 1つも無い                                                        |
| `進行中`        | `drafting` か `revising` の計画があり、作業を進められる          |
| `確認待ち`      | `drafting` か `revising` の計画があり、ユーザーの回答待ちで止まっている（待ち内容は `asis.md` に書く） |
| `完了`          | 1つ以上あり、すべて `complete`                                   |
| `中断`          | 問わない。再開条件を `asis.md` に書く                            |

前フェーズが `完了` になるまで、後続フェーズのフォルダに計画を作らない。
