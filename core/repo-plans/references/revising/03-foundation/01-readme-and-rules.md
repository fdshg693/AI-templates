# 基盤の定着: `worklog` の README と規約

> 記入例の時点: `revising`。[drafting](../../drafting/03-foundation/01-readme-and-rules.md) の案をレビューしてもらい、README と規約の文面を改訂した。次の時点は [complete](../../complete/03-foundation/01-readme-and-rules.md)。

## 目的と対象外

- 目的: 次の作業者（人とエージェント）が、README と規約だけで `worklog` の利用・検証・変更時の注意を把握できるようにする。
- 対象外: 実例のないディレクトリ・ルール・スキル、移行手順、配布方法。

## 前提

- [フェーズ2の完了](../../complete/02-minimal-delivery/01-add-and-list.md): 定着の候補は「利用・検証の入口」と「保存形式を変更するときの不変条件」の二点。
- ルート README には、フェーズ2で書いた利用例と検証コマンドがある。エージェント規約はまだ無い。

## 計画

### 実装から観測できた知見

- 利用者は README の目的と2つのコマンドを読むだけで、最初の利用と検証を始められた。
- 保存形式を変えると追加と一覧の両方に影響し、手で直した行の扱いも含めないと見逃す（デモで一覧が落ちた実例）。
- スキルを作る根拠となる反復はまだ無い。

### 正本の置き場

| 情報                        | 正本の置き場            | 理由                                            |
| --------------------------- | ----------------------- | ----------------------------------------------- |
| 目的、利用方法、検証、構成  | ルート README           | 利用者と作業者が最初に読む入口だから。          |
| 保存形式変更時の確認        | エージェント規約        | 変更するたびに必ず守る不変条件だから。          |
| 技術比較、デモ時の調整理由  | repo-plans の progress  | 今回限りの経緯であり、常時読む必要がないから。  |
| `WORKLOG_DIR`（テスト専用） | テストの先頭コメント1行 | 利用者向け機能ではないため、README に書かない。 |
| サブコマンド追加の手順      | 作らない                | 実績が無く、推測で手順を書くことになるから。    |
| 移行手順、配布方法          | 作らない                | ユーザーが今は不要と回答したため。              |

### 規約・案内文に入れる文面の案

README の先頭を、目的、利用例、検証、構成の順にする。

```markdown
# worklog

作業の区切りで一行のメモを残し、日付順に一覧するコマンド。

## 使い方

    python -m worklog add "認証APIの調査を完了"
    python -m worklog list

## 検証

    python -m unittest

## 構成

- `src/worklog/` - コマンドと保存・読込
- `tests/` - 自動テスト
```

規約の一文は、数を書かず、観測できる行動にする。

```markdown
保存形式（`.worklog/*.md` の行の書式）を変更するときは、追加、一覧、空データ、手で直した行のそれぞれを検証する。
```

## 完了条件と検証方法

- [ ] README の先頭から、目的・利用例・検証・構成を読める（改訂後の README を再提示して確認する）。
- [x] エージェント規約に、保存形式変更時の検証の一文がある。
- [ ] ルートの指示ファイルから `repo-plans/AGENTS.md` への参照を外した。
- [ ] `lint_repo_plans.py` がエラーなしで終わる。

## ユーザーとの対話

### 質問（回答まで、その判断に依存する作業を進めない）

- なし。

### レビュー項目（作業後に確認してもらう）

- 改訂後の README の最初の一文で、何のツールか分かるか。
- 数を外した規約の一文でよいか。

### 回答と反映

> 1. README を開いて最初に見えるのが使い方だと、何のツールか分からない。先に一文ほしい。
> 2. 規約の一文は要る。ただ「4つ」と数を書くと、増えたときに嘘になる。
> 3. 移行の話や、配布方法は今は書かなくていい。

| 受け取った内容            | 採否と理由                                             | 変更した箇所                   |
| ------------------------- | ------------------------------------------------------ | ------------------------------ |
| README の先頭に一文ほしい | 採用。目的の一文を使い方より前に置く。                 | 規約・案内文の文面案（README） |
| 「4つ」と数を書かない     | 採用。項目を列挙するだけにする。                       | 規約・案内文の文面案（規約）   |
| 移行・配布は今は書かない  | 採用。設計文書・スキルを作らず、必要時に別計画で扱う。 | 正本の置き場（「作らない」行） |
