# 仕様・技術確定: `worklog` の最初の縦切り

> 記入例の時点: `complete`。[revising](../../revising/01-specification-and-technology/01-worklog-first-slice.md) の改訂案を再提示し、ユーザーの合意を得てフェーズ2へ引き継いだ。

## 目的と対象外

- 目的: 利用者が一行の作業メモを保存し、別の実行で作成時刻とともに一覧できるようにする。
- 対象外: 同期、共有、認証、GUI、タグ、検索、編集、削除、保存先の指定、配布。

## 前提

- 依頼の原文と、まだ決めていないことは [ラフ案](../../rough/01-worklog-idea.md) にある。
- 新規リポジトリであり、既存のコード・設定・エージェント指示は無い。
- 利用者はチーム5人（Windows 3人、Mac 2人）。全員 Python 3.11〜3.13 を入れている（回答で確認）。

## 計画

### 最初の縦切り

```console
$ worklog add "認証APIの調査を完了"
$ worklog list
2026-09-16 14:32  認証APIの調査を完了
```

- `add` と `list` に限定し、一覧で作成時刻と本文を表示する。
- データが無い状態の `list` は「メモはまだありません」と表示して成功終了する。
- 保存先は利用者のホームディレクトリ直下の `.worklog/` に固定する。

### 技術選定の結論

| 判断     | 採用                                 | 理由（詳細は [progress](../../progress/01-technology-research.md)）                               |
| -------- | ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 保存形式 | 一日ごとの Markdown ファイル         | 直接開いて誤字を直せる。JSON は手で直すと括弧やカンマの崩れで全体が読めなくなる。                 |
| 実装環境 | Python 3.11 以上の標準ライブラリだけ | 全員の端末にある。版が揃っていないため、3.11 で動く機能だけを使う。依存関係と配布設定は作らない。 |

- 文字コードは環境の既定に任せず指定する。OS 固有の機能に依存しない。
- 保存形式は利用者が確認できる正本であり、一覧表示はその正本を読む。

## 未決事項と引継ぎ

- フェーズ2の実装対象: `add`、`list`、空データ時の表示、保存と一覧の自動テスト、最初の利用方法。
- フェーズ2の検証:
  - 空データで `list` する。
  - 1件追加して `list` する。
  - 日付をまたぐ複数件を追加して `list` する。
  - 保存ファイルを直接開き、手で直した内容が `list` に反映されることを確認する。
- 実装で注意すること: 版の幅（3.11〜3.13）と Windows・Mac 双方で動くこと。文字コードを明示すること。
- レビュー: 実行例と表示結果をユーザーへ示し、日常の作業メモとして使えるかを確認する。
- 将来の候補: 本文の検索（メモが溜まってから必要性を判断する）。
- 技術比較の経緯は [progress/01-technology-research.md](../../progress/01-technology-research.md) に置き、フェーズ2の作業指示には使わない。
