# 基盤の定着: `worklog` の README と規約

> 記入例の時点: `complete`。[revising](../../revising/03-foundation/01-readme-and-rules.md) の改訂を反映し、利用者の確認を受けて3フェーズを終えた。

## 目的と対象外

- 目的: 次の作業者（人とエージェント）が、README と規約だけで `worklog` の利用・検証・変更時の注意を把握できるようにする。
- 対象外: 実例のないディレクトリ・ルール・スキル、移行手順、配布方法。

## 前提

- [フェーズ2の完了](../../complete/02-minimal-delivery/01-add-and-list.md): 定着の候補は「利用・検証の入口」と「保存形式を変更するときの不変条件」の二点。

## 計画

### 正本の置き場（確定）

| 情報                        | 正本の置き場            | 理由                                            |
| --------------------------- | ----------------------- | ----------------------------------------------- |
| 目的、利用方法、検証、構成  | ルート README           | 利用者と作業者が最初に読む入口だから。          |
| 保存形式変更時の確認        | エージェント規約        | 変更するたびに必ず守る不変条件だから。          |
| 技術比較、デモ時の調整理由  | repo-plans の progress  | 今回限りの経緯であり、常時読む必要がないから。  |
| `WORKLOG_DIR`（テスト専用） | テストの先頭コメント1行 | 利用者向け機能ではないため、README に書かない。 |
| サブコマンド追加の手順      | 作らない                | 実績が無く、推測で手順を書くことになるから。    |
| 移行手順、配布方法          | 作らない                | ユーザーが今は不要と回答したため。              |

### 定着した文面

- ルート README: ツールの目的の一文、`add` と `list` の利用例、検証入口、主要な構成（文面は [revising](../../revising/03-foundation/01-readme-and-rules.md) の案のとおり）。
- エージェント規約: 「保存形式（`.worklog/*.md` の行の書式）を変更するときは、追加、一覧、空データ、手で直した行のそれぞれを検証する。」
- 専用スキルは作らない。見送った理由は [progress/03-foundation.md](../../progress/03-foundation.md) に残した。

## 完了条件と検証方法

- [x] エージェント規約に、保存形式変更時の検証の一文がある。
- [x] ルートの指示ファイルから `repo-plans/AGENTS.md` への参照を外した。
- [x] `lint_repo_plans.py` がエラーなしで終わる。

## ユーザーとの対話

### 質問（回答まで、その判断に依存する作業を進めない）

- なし。

### レビュー項目（作業後に確認してもらう）

- 改訂後の README の最初の一文で、何のツールか分かるか。
- 数を外した規約の一文でよいか。

### 回答と反映

| 受け取った内容                                          | 採否と理由                                             | 変更した箇所                   |
| ------------------------------------------------------- | ------------------------------------------------------ | ------------------------------ |
| README の先頭に一文ほしい                               | 採用。目的の一文を使い方より前に置く。                 | 定着した文面（README）         |
| 「4つ」と数を書かない                                   | 採用。項目を列挙するだけにする。                       | 定着した文面（規約）           |
| 移行・配布は今は書かない                                | 採用。設計文書・スキルを作らず、必要時に別計画で扱う。 | 正本の置き場（「作らない」行） |
| 再提示への返答「README の最初の一文と、規約の書き方でいい。」 | 合意。                                            | 完了条件                       |

## 未決事項と引継ぎ

- 検索、タグ、編集、削除、配布を追加する場合は、既存コードベースの変更として新しい `plans/` の計画を作る。ただし、利用者層や保存先が変わる場合は [next-slice-boundary.md](../../next-slice-boundary.md) の基準で repo-plans に戻す。
- 保存形式の移行が必要になった場合は、移行対象と互換性を明記した別の縦切りとして扱う。
- 最終的な完了範囲と検証結果は [progress/99-completion.md](../../progress/99-completion.md) を参照する。
