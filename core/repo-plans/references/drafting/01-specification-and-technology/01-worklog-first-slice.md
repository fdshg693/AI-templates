# 仕様・技術確定: `worklog` の最初の縦切り

> 記入例の時点: `drafting`。[ラフ案](../../rough/01-worklog-idea.md)を整理し、初期案を提示して回答を待っている。実装はまだしない。次の時点は [revising](../../revising/01-specification-and-technology/01-worklog-first-slice.md)。

## 目的と対象外

- 目的: 利用者が一行の作業メモを保存し、別の実行で追加順に一覧できるようにする。
- 対象外: 同期、共有、認証、GUI、タグ、検索、編集、削除、保存先の指定。

## 前提

- 依頼の原文と、まだ決めていないことは [ラフ案](../../rough/01-worklog-idea.md) にある。
- 新規リポジトリであり、既存のコード・設定・エージェント指示は無い。
- 依頼者の端末は Windows。チーム全体の実行環境は未確認。

## 計画

### 最初の縦切り

最終的に次のように使えれば、最初の縦切りは成立とみなす。

```console
$ worklog add "認証APIの調査を完了"
$ worklog add "レビュー指摘を反映"
$ worklog list
認証APIの調査を完了
レビュー指摘を反映
```

- データがまだ無い状態で `list` しても失敗しない。
- 上の表示は仮のもの。作成時刻を出すかどうかは質問3の回答で決める。

### 技術選定の比較

| 判断     | 候補                                    | 比較に必要な事実                                                             |

| 保存形式 | Markdown、JSON                          | 利用者が直接確認・修正できるか。追加と一覧だけを無理なく実装できるか。       |
| 実装環境 | チーム標準の Python、別の新規ランタイム | 初期利用者の環境に既にあるか。外部依存なしでコマンドとテストを提供できるか。 |

## ユーザーとの対話

### 質問（回答まで、その判断に依存する作業を進めない）

> 依頼内容から最小のものを作る前に、三点だけ教えてください。どれも、答えによって作るものが変わります。
>
> 1. 最初に使うのは依頼者本人とチームの開発者だけでよいですか。それとも、初回から他の部署などへ配る前提ですか。（前者なら配布の仕組みは作りません）
> 2. 保存したメモを、後からテキストエディタで開いて直すことはありそうですか。直すなら、人が読める形式で保存します。直さないなら、機械向けの形式も選べます。
> 3. 一覧には本文だけで足りますか。それとも「何時にやったか」も必要ですか。日報用途とのことなので必要と推測していますが、確認させてください。
>
> また、チームの Python の有無と版も教えてください。
