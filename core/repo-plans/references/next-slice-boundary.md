# 完了後に来た二つの要望を振り分ける例

> これは `plans` テンプレートの `references/tag-popularity-sort.md`（既存リポジトリへの小さな機能追加の例）に対応する境界の例である。`plans` は別テンプレートであり、導入先に無い場合もあるのでリンクにしていない。repo-plans は新規リポジトリを立ち上げる3フェーズを扱い、既存リポジトリへの小さな変更を扱わない。

## 起きたこと

`worklog` を使い始めて3週間後、利用者から二つの要望が届いた。

> A. 一覧が長くなってきた。「今日のぶんだけ」「この日だけ」見たい。
>
> B. 隣のチームの人が使ってみたいと言っている。メモをチーム全員で見られるようにして、誰が何をやっているか分かるようにしたい。

## A: `plans/` で扱う

既存の一覧処理へ引数を一つ足す変更であり、目的、技術、基盤は変わらない。保存形式、利用者層、保存先もそのままである。

作る計画: `plans/worklog-list-date-filter.md`

```markdown
# `list --date` で日付を絞り込む

## 目的と対象外

- 目的: `worklog list --date 2026-09-16` で、その日のメモだけを表示する。
- 対象外: 期間指定、`--today` などの別名、本文での絞り込み。

## 先に読むもの

- README、エージェント規約（保存形式を変えないので、追加・一覧・空データ・手で直した行の検証は一覧側だけで足りるか確認する）。

## 完了条件

- 指定日のメモだけが日付見出し付きで表示される。
- 該当日が無いときは「メモはありません」と表示し、成功終了する。
- `YYYY-MM-DD` 以外の値はエラー（終了コード 2）にする。
```

## B: repo-plans のフェーズ1へ戻る

次の前提が変わる。小さな機能追加として `plans/` に収めると、前提を決める作業が飛ばされる。

| 変わる前提         | 今まで                                  | 要望B                                         |
| ------------------ | --------------------------------------- | --------------------------------------------- |
| 利用者層           | チーム5人、全員が自分の端末だけを使う   | 複数チームで、他人のメモを読む                |
| 保存先             | 各自のホームの `.worklog/`              | 共有の保存先が必要（置き場所、認証が未決）    |
| 対象外にしていた事 | 同期、共有、認証                        | すべて対象内になる                            |
| 保存形式の前提     | 一日一ファイル、手で直す                | 複数人の同時追記、他人のメモの扱いが必要      |

新しい repo-plans のフェーズ1で、まず次をユーザーへ質問する。

> 共有したい範囲は、メモの全文ですか、それとも「今日やったことの件名」だけですか。見せたくないメモを書く場合はどうしますか。共有の置き場所は、既にチームが使っているものがありますか。

この回答の前に、保存先や同期の技術を選ばない。

## 振り分けの基準

- 既存の目的、利用者層、保存形式のどれも変えない → `plans/`。
- いずれかを変える、または対象外にしていた事項（同期、共有、認証、配布）が対象内になる → repo-plans のフェーズ1。
