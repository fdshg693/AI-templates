# progress: `worklog` の実行時詳細

> [実行例の入口](../README.md) にあるフェーズ計画を読めば、次の作業へ進める。ここには、比較の詳細、実装中の判断、検証結果を置く。後続作業の指示を progress だけに残さない。

## 記録一覧

- [01-technology-research.md](01-technology-research.md) - 保存形式と実装環境の比較、小さな試行の結果
- [02-minimal-delivery.md](02-minimal-delivery.md) - 最小実装、文字化け、テストの副作用、デモ後の改訂の実行記録
- [03-foundation.md](03-foundation.md) - README と規約への定着、スキル化を見送った記録
- [99-completion.md](99-completion.md) - 3フェーズ全体の完了範囲と検証結果

## 本文との棲み分け

| 内容                             | 計画本文               | progress               |
| -------------------------------- | ---------------------- | ---------------------- |
| 目的、対象外、完了条件、次の作業 | 正本として更新する     | 書かない               |
| ユーザー回答と採否               | 要約して記録する       | 必要なら詳細を残す     |
| 比較表、試行結果、実装中の細部   | 要約とリンクだけ残す   | 記録する               |
| 完了範囲と検証結果               | フェーズ完了に要約する | 具体的な結果を記録する |

最終記録を書いてから、フェーズ全体を完了扱いにする。
