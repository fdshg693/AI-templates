# フェーズ2実行記録: 最小実装と利用者デモ

> [フェーズ2の計画](../drafting/02-minimal-delivery/01-add-and-list.md) を実行して生じた詳細。後続の作業内容は [改訂案](../revising/02-minimal-delivery/01-add-and-list.md) と [完了](../complete/02-minimal-delivery/01-add-and-list.md) に反映済みである。

## 実装した最小構成

- コマンド入口は `add` と `list` だけを受け付ける。
- `add` は当日の Markdown ファイルへ、`- HH:MM 本文` を一行ずつ追記する。
- `list` は日付ファイルを昇順に読み、各日の見出し、時刻、本文を表示する。
- 保存ディレクトリが無いときの `list` は「メモはまだありません」を表示する。

## 実装中に見つかったこと

### 1. Windows で日本語が文字化けした

Windows の端末で、Mac で作ったテストデータを読むと文字化けした。`open()` に文字コードを指定しておらず、Windows では既定が cp932、Mac では UTF-8 だったため。

```text
# 修正前（Windows）
- 14:32 隱崎ｨｼAPI縺ｮ隱ｿ譟ｻ繧貞ｮ御ｺ・
```

対応: 読み書きすべてで `encoding="utf-8"` を明示した。テストに、日本語を書いて読み戻す確認を追加した。

### 2. テストが実際のメモを書き換えた

最初のテストは `~/.worklog/` へそのまま書いており、実行した開発者の実際のメモに「テスト用メモ」が混ざった。

対応: 保存先を環境変数 `WORKLOG_DIR` で上書きできるようにし、テストは一時ディレクトリを指す。フェーズ1で「保存先指定」は対象外としたため、これは利用者向け機能ではなくテスト専用とし、README には書かない。

### 3. 日付またぎのテスト

当日の日付を実行時刻から取ると、深夜0時付近でテストが不安定になる。時刻を外から渡せる形にし、`23:59` から `00:01` をまたぐ場合を固定値で再現した。

## 検証結果（初回デモ前）

| 操作                                | 期待                                     | 結果 |
| ----------------------------------- | ---------------------------------------- | ---- |
| 空データで `list`                   | 失敗せず空である旨を表示する             | 成功 |
| 1件の `add` 後に `list`             | 本文と作成時刻を表示する                 | 成功 |
| 別日に2件追加して `list`            | 日付順・日内追加順で表示する             | 成功 |
| 空の本文で `add`                    | 保存せず終了コード 2                     | 成功 |
| 改行を含む本文で `add`              | 保存せず終了コード 2                     | 成功 |
| 日本語を `add` して Windows で読む  | 文字化けしない                           | 成功 |
| Markdown を直接開く                 | 追記内容を人が確認できる                 | 成功 |

## デモで分かったこと

- 日付が行ごとに繰り返され、日の境界が追いにくかった。日付ごとの見出しに変更した。
- ユーザーが保存ファイルへ `## 午前` と書き込むと `list` が例外で落ちた。初回デモ前の検証には「手で直したファイル」が無く、見逃していた。形式に合わない行はそのまま表示するようにし、テストを追加した。

  ```console
  $ cat ~/.worklog/2026-09-16.md
  - 09:12 レビュー指摘を反映
  ## 午前
  - 14:32 認証APIの調査を完了
  $ worklog list
  Traceback (most recent call last):
    ...
  ValueError: 形式に合わない行: '## 午前'
  ```

  原因: 初期実装は、`- HH:MM 本文` の形に合わない行を「あり得ない」として例外にしていた。フェーズ1で「人が直す」ことを要件にしたのに、形式外の行を読む挙動を決めていなかった。
- 保存形式と追加処理は変えていない。

## 検証結果（改訂後）

| 操作                                   | 期待                                   | 結果 |
| -------------------------------------- | -------------------------------------- | ---- |
| 日付をまたぐ2件を `list`               | 日付見出しの下に時刻と本文が並ぶ       | 成功 |
| `## 午前` を含むファイルを `list`      | 落ちず、その行を時刻なしで表示する     | 成功 |
