> [フェーズ1の改訂案](../revising/01-specification-and-technology/01-worklog-first-slice.md) の根拠となった詳細記録。フェーズ2は改訂済みの計画本文を正本にして進める。

## 比較した保存形式

| 候補                   | 確認した利点                                       | 最初の縦切りでは見送った理由                                                            |
| ---------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 一日ごとの Markdown    | 追記内容と時刻を直接読める。日付単位で分割できる。 | 採用。                                                                                  |
| JSON                   | 構造化した検索やタグを追加しやすい。               | 「たまに手で直す」と回答があり、手の修正で括弧やカンマが崩れると全体が読めなくなる。    |
| 単一のプレーンテキスト | 実装が最も小さい。                                 | 日付と時刻の境界を保つ形式を別に決める必要があり、一ファイルが際限なく大きくなる。      |

## 小さな試行

JSON の壊れ方を確認した。手でカンマを一つ消した状態を読み込ませると、メモ全件が読めなくなった。

```console
$ python -c "import json; json.load(open('2026-09-16.json', encoding='utf-8'))"
json.decoder.JSONDecodeError: Expecting ',' delimiter: line 4 column 3 (char 71)
```

Markdown は一行が崩れても、他の行は読める。この差が採用の決め手になった。

## 実装環境の確認

- 依頼者へ確認し、Python が全員の端末にあることを確認した。版は 3.11、3.12、3.13 が混在。
- コマンド引数（`argparse`）、日時（`datetime`）、ファイル入出力（`pathlib`）、テスト（`unittest`）は標準ライブラリで満たせることを小さな試行で確認した。3.11 でも動く範囲の機能だけを使う。
- 新しいランタイムや依存関係を導入すると、最小実装より導入・配布の判断が先に増えるため見送った。
