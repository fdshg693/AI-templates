# ラフ案: ローカル作業メモを残す `worklog`

> これは詳細計画へ移行済みのラフ案である。実際の作業では `drafting` から始め、フェーズ1の計画を作り始めた時点で `promoted` に更新する。

## 依頼の原文

> 夕方に日報を書こうとすると、午前に何をやったか思い出せない。作業の切れ目にコマンドで一行だけ残して、あとで一覧で見られるようにしたい。エディタを開くほどではない。チームの他の人にも使ってもらえるかもしれない。

## 何をしたいか

- 作業の区切りで `worklog add "..."` のように一行を残し、後から日付順に一覧したい。
- 日報を書く用途なので、「いつやったか」が分かることが重要そうである（未確認）。

## まだ決めていないこと

- 保存形式。依頼者は「あとで自分で開いて直すかもしれない」と言っていたが、頻度は不明。人が直せることと、機械で扱いやすいことのどちらを優先するか決まっていない。
- 「他の人にも」が、今すぐ配るという意味か、将来の希望かが不明。
- 作成時刻、タグ、検索、編集、削除のどこまでを最初に含めるか。
- 利用者の実行環境。依頼者の端末は Windows だが、チーム全体は未確認。

## 検討したが今は採らない案

- 既存のメモアプリや課題管理ツールへの投稿。依頼者が「コマンドで一行」を求めており、外部サービスの導入判断が先に必要になるため。ただし依頼者が既に使っているものがあるかは、ユーザーへ確認する。

## 次にすること

1. 初期利用者、保存データを直接編集する頻度、配布の必要性、チームの実行環境をユーザーへ確認する。
2. 保存形式と実行環境の候補を、最初の縦切りに必要な条件だけで比較する。
3. 回答を待つ必要がある点を明記したフェーズ1の初期案を作る。
