# セッションを取り込む

学習者が `inbox/` にエクスポートしたファイルを置いたとき、または「ログを置いた」「見て」と言われたときに読む。取り込んだら続けて [reviewing.md](reviewing.md) に進む。

## 作るもの

`sessions/YYYY/YYYY-MM-DD-{slug}.md`（`status: unreviewed`）。書式は [formats.md「セッション」](formats.md#セッションsessionsyyyy)。

## 手順

1. `inbox/` のファイルを一覧する。`.md` 以外は取り込まない（中身を確かめ、Markdown でエクスポートし直すよう学習者に頼む）。
2. 練習した日を決める。既定はファイルの更新日（エクスポートした日）。学習者が別の日を伝えた場合は `--date` を使う。`--date` は inbox のすべてのファイルに同じ日付を付けるので、日付の違うファイルは1つずつ inbox に置いて実行する。
3. リポジトリのルートで取り込む。

   ```bash
   uv run practice-review/practice.py ingest practice-review [--date YYYY-MM-DD] [--source chatgpt]
   ```

4. 出力を確かめる。
   - `ingest:` 取り込めた。inbox から消えている。
   - `skip: … と同じ内容` 取り込み済みのもの。inbox から消す。
   - `refuse: … の続き` 下の「同じスレッドの再エクスポート」に従う。
5. lint を実行し、エラー0にする（inbox の警告が消えていることも確かめる）。

## 同じスレッドの再エクスポート

1スレッド＝1セッションとして扱う。学習者には、続きを練習するときは新しいスレッドを始めてもらう。セッションの本文は取り込み後に書き換えないので、続きを同じファイルに足すと、どこまでレビューしたか分からなくなるため。

再エクスポート（取り込み済みのセッションの本文＋続き）が置かれたら、次のどちらかにする。

- inbox のファイルから、取り込み済みのセッションと重なる先頭部分を削除して、もう一度 `ingest` する。続きの部分だけが新しいセッションになる。
- 重なりを残したままでよいと学習者が言った場合だけ、`--force` を付ける（重なった部分が2回レビューされる）。

## 完了条件

- [ ] `inbox/` に `.gitkeep` 以外のファイルが無い
- [ ] 取り込んだセッションの `date` が練習した日になっている
- [ ] lint がエラー0で終わる
