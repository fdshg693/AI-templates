# スレッドテンプレート ラフプラン（ユーザーの元アイデア）

## 背景（ユーザー談）

`core/plans` は悪くないが、ある程度スコープが狭まっているときに威力を発揮する。複数のプランにまたがる機能変更や、そうした大規模タスク実装時の手戻り・仕様変更に対応しようとするとプランがぐちゃぐちゃになる。そこで「スレッド」というプランを内包したテンプレートを作りたい。

## アイデア（原文の要点）

- 2重管理をさけ、`core/plans` を Junction で中に取り込む（できたらややこしいのでフォルダ名だけ変えたい）
- 他にスレッドを記載するフォルダを作る
- スレッドはトピックごとに関連するプランなどをまとめる
- 複数のプランにまたがるような場合は、まずスレッドにプランを書き、プランの順序関係、実装時に発覚した事実などを追記していき、時系列に記録する
- プラン・スレッドは双方をフロントマターで関連付けられる（また同一スレッドに所属するプラン同士も）

## 迷っている点（詳細プラン化の時点で洗い出したもの）

- Junction を git にコミットできるか（Git for Windows はジャンクションを絶対パスのシンボリックリンクとして記録する可能性がある）。他 OS での clone、導入先へのコピーで実体が付いてくるか。
- 取り込んだプランのフォルダ名（`plans` 以外）とスレッドのフォルダ名。
- plans の「完了したプランは削除する」運用と、スレッドからのリンクが切れる問題。
- progress（プラン内の詳細記録）とスレッドの時系列記録の棲み分け。
