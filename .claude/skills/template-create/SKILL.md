# template-create

[template-review](../template-review/SKILL.md) と対になる作成用スキル。完成の判定基準は template-review の「評価基準」1〜10（正本）で、**全項目 A** を目標に作る。本ファイルは、その基準を満たすための作る順番と決め方だけを書く。

## 成果物の構成

```text
core/<name>/
├── AGENTS.md          # エージェント向けの正本（入口）。目安150行以内
├── CLAUDE.md          # `@./AGENTS.md` の1行＋役割分担コメントだけ
├── README.md          # 人間向け: 何のテンプレートか・誰向けか・導入手順。導入先にはコピーしない
├── guides/            # ルールと手順の正本。1ファイル1場面
├── references/        # コピー先と同じ構造の記入例。ルール本文は書かない
└── lint_<snake>.py    # 成果物が規約に沿っているかの検査（標準ライブラリのみ）
```

`<name>` はケバブケース、`<snake>` はそのスネークケース（`repo-plans` → `lint_repo_plans.py`）。

## 手順

### 1. 要件を固める（ファイルを作る前）

次の5点を箇条書きにしてユーザーに提示し、合意してから先へ進む。不明な点は推測で埋めず、選択肢を添えて質問する。

| 決めること                                             | 例（plans の場合）                                               | 効く評価基準 |
| ------------------------------------------------------ | ---------------------------------------------------------------- | ------------ |
| 目的と対象外（既存テンプレートとの境界）               | 既存コードへの機能追加。新規リポジトリは repo-plans              | 2, 6         |
| コピー先の置き場所                                     | 導入先の `plans/`                                                | 7            |
| 場面の一覧（エージェントがこのテンプレートで行う作業） | ラフプラン作成 / プラン作成 / プラン実行                         | 3            |
| 成果物の一覧（場面ごとに作る・更新するファイルと書式） | 概要・ステップ・progress。frontmatter の `type` / `status`       | 1, 10        |
| 不変条件（違反すると誤った成果物になるもの）と理由     | `status` は決められた値だけ。理由: lint と後続作業が値に依存する | 5, 8         |

既存の `core/*/AGENTS.md` と README の目的を読み、重複するテンプレートを作らない。重複するなら既存テンプレートの拡張を提案する。

### 2. 雛形を生成する

リポジトリルートで実行する。既存フォルダがあれば中止する。

```bash
uv run .claude/skills/template-create/scripts/scaffold_template.py core/<name> --guides <scene-a>,<scene-b>
```

AGENTS.md・CLAUDE.md・README.md・`guides/<scene>.md`・`references/example.md`・`lint_<snake>.py` を作る。生成物の `TODO:` は手順3〜6ですべて埋めるか消す（`--help` で他のオプション）。

### 3. guides を書く（ルールの正本）

- 1場面＝1ファイル。場面ごとに「いつ読むか」「何を作るか」「手順」「完了条件」の順で書く。
- ルールは確認できる行動・成果物（ファイル、見出し、frontmatter 値、チェックボックス）で書く。「適切に」「意識する」は使わない。
- 禁止事項には1行の理由を添える（エージェントが例外を判断できるように）。
- 状態値・必須見出し・命名規則などの一覧は、1つのガイドにだけ表で書き、`lint_<snake>.py` の定数に「このガイドと同期」とコメントする。他の場所は要約＋リンクにする。
- 特定の AI ツール・OS・言語を前提にしない。ツール固有の進め方が要るなら任意のガイドに分け、README で「使わなければ削除してよい」と書く。

### 4. references を書く（例の正本）

- `references/` 内のパス＝コピー先のパスにする。`references/` 内のリンクは `references/` の外を指さない（コピー先に存在しない）。
- 成果物の種類ごとに1つ置き、**書き方の判断が違うものだけ**を増やす。題材や状態が違うだけのファイルは作らない。
- ルール本文は書かず、ガイドへのリンクにとどめる。架空の題材で、そのまま読める完成状態に書く（状態をどう読み替えるかは AGENTS.md の「サンプル」節に書く）。
- プレースホルダは `{name}` に統一し、置換必須のものは README の導入手順に一覧で書く。

### 5. lint を書く

生成された `lint_<snake>.py` の `FILE_RULES`・`REQUIRED_FILES` を手順1の成果物一覧に合わせる。雛形は次を検査済み: frontmatter の有無・`type`・`status`、必須見出し、相対リンク切れとフォルダ外リンク、残ったプレースホルダ。テンプレート固有の整合（依存関係、状態の連動など）は関数を足す。

- エラーは `path:line: message` 形式、エラーがあれば非0終了。
- `--examples` で `references/` 自体を検査できること。
- 動作確認: `references/` に対して通ること、`references/` の1ファイルをスクラッチパッドにコピーして必須見出しや `status` を崩すと失敗すること、の両方を確かめる。

### 6. AGENTS.md / CLAUDE.md / README を仕上げる

- **AGENTS.md**: 目的1〜2文 → 「場面 → 読むファイル」表（全ガイドにリンク）→ 不変条件（各1行＋正本へのリンク）→ サンプル表（成果物 → reference）→ 「このテンプレートを編集するとき」節（正本の位置、プレースホルダ記法、同時に更新すべき組（ガイドの表 ⇔ lint の定数）、lint コマンド）。背景・経緯は README へ。
- 全ファイルが AGENTS.md から2ホップ以内で届くようにする。
- **README.md**: 何のテンプレートか・対象・含まれるもの → 導入手順（コピーするものの表、リネーム・置換するプレースホルダ、ルートの指示ファイルへの1行追加、導入直後の lint 実行）→ 同梱スクリプトのコマンド。エージェント向けルールは書かず AGENTS.md にリンクする。
- AGENTS.md 内のコマンドはコピー先のパス（`uv run <name>/lint_<snake>.py <name>`）、「このテンプレートを編集するとき」節はテンプレート置き場のパス（`core/<name>/...`）で書き、どちら向けか分かるようにする。

### 7. 検証する

リポジトリルートで次を実行し、出力を確認する。

```bash
uv run core/<name>/lint_<snake>.py --examples core/<name>/references
uv run .claude/skills/template-review/scripts/inspect_template.py core/<name>
```

inspect の結果で次がすべて満たされるまで直す: リンク切れ・フォルダ外リンク0、到達不能ファイル0、常時ロード150行以内、`TODO:` 0、reference の近似重複は意図したものだけ。

最後に template-review の手順3（典型タスクを1つ想定し、AGENTS.md からリンクを辿って必要なファイルだけ読む）を自分で行い、着手できることを確かめる。C・B が残れば直す。

### 8. 登録する

- リポジトリルートの [README.md](../../../README.md) の「core の中身」に1行足す。
- 既存テンプレートとの境界がある場合は、相手の README にも「〜は別テンプレート `<name>` で扱う」と1行足す。
- 成果物が積み重なった状態の例が要るなら、`references/` を増やさずに `starter/<name>-<題材>/` にスターターを作る。作り方とルールは [starter/README.md](../../../starter/README.md)。作ったら `uv run starter/check_starters.py` を通す。
